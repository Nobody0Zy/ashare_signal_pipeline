# 实验谱系收尾 Playbook（通用版）

> 创建日期: 2026-09-30
> 定位: **通用收尾流程**——任何实验谱系跑完后，把一个「结论已足、工程未收」的状态，收束为「可交接、可复现、可引用」的状态。
> 抽象来源: `strategy_explore` 仓库 `design/v5/discussion/closeout_map/01_v5_first/02_v5_plan.md`，已剥离 v5 专属目录名与 experiment_version。
> 范例: v5 是本流程的完整实例。需要对照时读 `strategy_explore` 仓库 `design/v5/discussion/closeout_map/01_v5_first/` 下的 `01_v5_analysis.md`（判断）与 `02_v5_plan.md`（执行规范）。

---

## 0. 适用判断：什么时候该收尾

收尾的触发条件不是「实验跑完」，而是「**结论够用了，但工程还没收口**」。典型信号：

| 信号 | 说明 |
| :--- | :--- |
| 结论层已完成 | 谱系要回答的核心问题已有明确答案 |
| 工程层未完成 | 状态口径、目录边界、canonical 定版、复现说明、问题归属都还没理 |
| 存在未收敛的工作区 | git 工作区里该谱系的改动与其他改动混在一起 |
| 存在口径漂移风险 | 文档描述与实际落盘结果已经不一致 |
| 未知哪次 run 才算正式结果 | canonical / failed / aborted 没有定版 |

> v5 的实例判断见其 `01_v5_analysis.md` §2、§6。

## 1. 执行边界（收尾前先立规矩）

**做**：

1. 状态对齐（谱系全局文档 + 该谱系各设计子文档）
2. 全部相关目录盘点（定义层 / 结果层 / 数据层）
3. canonical artifact map（结果定版）
4. 复现锚点说明
5. 问题移交清单
6. git 工作区分组建议

**明确不做**：

1. 不重跑任何 pipeline step
2. 不删除、不移动任何现有工件
3. 不做整轮 archive / prune
4. 不抽象框架外壳
5. 不启动新样本数据谱系
6. 不执行 commit（只输出分组建议）

**硬约束**：

1. 目标文件若存在与该任务冲突的未提交改动 → 先停止并报告，不覆盖
2. 允许新增的文件范围要事先锁定（通常只允许产出 Phase 3/4/5 的交付文档）
3. 允许修改的既有文件范围要事先锁定（通常只允许改「状态类字段」，不改数值、不改结论）

## 2. 七个阶段

每个 Phase 结束后直接进入下一个，不等待人工确认；但触发下节「阻塞处理」情形时必须停下提问。

### Phase 0 — 审计

| 项 | 内容 |
| :--- | :--- |
| 目标 | 动手前确认现状与阻塞 |
| 动作 | ① 查 `git status --short` 与当前分支；② 读谱系全局文档的状态口径；③ 读各设计子文档的状态字段；④ 确认相关目录是否都存在；⑤ 确认导航入口链是否完整 |
| 验收 | 输出审计报告，写明「本次会改哪些文件、哪些明确不碰、是否存在未提交冲突改动」 |
| 分支 | 无阻塞 → 直接进 Phase 1；有阻塞 → 只输出阻塞报告并停止 |

#### Phase 0 提示词模板

```text
请只做 <谱系名> 收尾的审计，不做任何修改。要求：
1. 输出当前分支与 git status --short 摘要。
2. 报告 <谱系全局文档> 的状态口径，以及 <各设计子文档> 的状态字段。
3. 确认这些目录是否存在：<定义层 / 结果层 / 数据层目录清单>。
4. 说明本次会改哪些文件、哪些明确不碰、是否存在未提交的冲突改动。
5. 只输出审计报告，不修改任何文件。
```

### Phase 1 — 状态对齐

| 项 | 内容 |
| :--- | :--- |
| 目标 | 把谱系状态口径同步为当前事实 |
| 动作 | 修改谱系全局文档与各设计子文档的**状态类表述与日期** |
| 验收 | 旧状态词不再出现；diff 仅涉及状态行与日期 |
| 红线 | **只改状态类表述与日期，不改实验数值、不改结论、不新增内容** |

#### Phase 1 提示词模板

```text
请只做 <谱系名> 状态对齐，不扩展范围。要求：
1. 更新 <谱系全局文档> 的状态口径，去掉过时的「待启动/进行中」表述。
2. 把 <设计子文档清单> 的状态由「设计中」改为「已执行」。
3. 只改状态类表述与日期，不改实验数值、不改结论、不重跑 pipeline、不动 data/raw。
4. 完成后输出 diff 摘要。
```

### Phase 2 — 目录盘点与导航收口

| 项 | 内容 |
| :--- | :--- |
| 目标 | 确认全部相关目录的结构与命名，形成清单 |
| 动作 | 按三层逐层列出顶层内容；记录缺失项、命名不一致项、结构异常项；确认导航入口链完整 |
| 验收 | 三层各有清单；异常项被显式列出（无异常则写明「无」）；**只读盘点，不移动不删除** |

#### 三层目录分类

| 层 | 保存什么 | 回答的问题 |
| :--- | :--- | :--- |
| 定义层 | 配置、设计、分析与执行依据 | 这个谱系是什么、为什么这样做 |
| 结果层 | 正式输出、模型与可引用结果目录 | 正式口径是什么 |
| 数据层 | step 派生物与母库等可重跑依赖 | 还能不能复现 |

#### Phase 2 提示词模板

```text
请对 <谱系名> 相关目录做只读盘点，不做任何移动或删除。要求：
1. 盘点定义层（<目录>）、结果层（<目录>）、数据层（<目录>）。
2. 逐层列出顶层内容，标出缺失项、命名不一致项、结构异常项。
3. 确认 <导航入口目录> 的入口链完整。
4. 只输出清单与异常项，不修改任何文件。
```

### Phase 3 — canonical artifact map（结果定版）

| 项 | 内容 |
| :--- | :--- |
| 目标 | 为该谱系的每个 experiment_version 唯一归类 |
| 动作 | 产出 artifact map：逐个判定 `canonical` / `failed` / `aborted`，写明判定依据；给出正式引用口径 |
| 验收 | 每个 experiment_version 有唯一归类；**canonical 在同一逻辑实验内唯一**；failed / aborted 均写明原因；未修改任何结果层 / 数据层内容 |

#### 三类状态定义

| 类别 | 是什么 | 用途 |
| :--- | :--- | :--- |
| canonical | 正式结果目录，后续引用、复现、汇报都以它为准 | 正式口径 |
| failed | 跑到失败，保留了 metadata / traceback / 局部工件 | 问题诊断 |
| aborted | 人工停止或未完成，只剩局部派生物或中间数据 | 生命周期治理 |

#### Phase 3 提示词模板

```text
请为 <谱系名> 生成 canonical artifact map，写入 <目标路径>。要求：
1. 只做归类与说明，不删除、不移动任何实验工件。
2. 对结果层下每个 experiment_version 逐一判定 canonical / failed / aborted，并写明原因。
3. 已知需复核的条目：<逐条列出待复核事实，要求自行验证不得照抄>。
4. 输出正式引用口径：哪些目录可引用、哪些只保留审计价值。
```

### Phase 4 — 复现锚点

| 项 | 内容 |
| :--- | :--- |
| 目标 | 确保该谱系后续可重跑 |
| 动作 | 产出复现文档：config 清单、state-file 命名规则、step 标准命令模板、分析脚本入口、结论 ↔ experiment_version 对照 |
| 验收 | 按文档可写出完整重跑命令序列；明确 state-file 不复用、与 config 一一对应；未执行任何 pipeline 命令 |

#### Phase 4 提示词模板

```text
请为 <谱系名> 生成最小复现说明，写入 <目标路径>。要求：
1. 列出 canonical config 清单与建议的 state-file 命名规则。
2. 给出各 step 的标准命令模板，并说明每实验独立 state-file、不复用。
3. 给出分析脚本入口与结论 ↔ experiment_version 对照。
4. 只写文档，不执行任何重跑命令，不删除任何工件。
```

> 命令模板必须使用**真实的 CLI 签名**，不要凭「理想接口」编写。见 [03_pitfalls.md](03_pitfalls.md) 的「CLI 语法」条目。

### Phase 5 — 问题移交

| 项 | 内容 |
| :--- | :--- |
| 目标 | 把本次暴露的问题整理成持久清单，移交给下一阶段 |
| 动作 | 每条写明：**现象 / 证据 / 影响 / 建议归属阶段** |
| 验收 | 每条都有证据（指向具体目录或文件）与明确归属；未改动下一阶段的既有文档 |

#### Phase 5 提示词模板

```text
请把 <谱系名> 暴露的问题整理成 <目标路径>。要求：
1. 覆盖 <问题类别清单>。
2. 每条写：现象、证据（指向具体目录或文件）、影响、建议归属阶段。
3. 不修改 <下一阶段> 下现有文档，不删除任何工件。
```

### Phase 6 — git 工作区分组建议

| 项 | 内容 |
| :--- | :--- |
| 目标 | 输出分组建议，**不执行 commit** |
| 动作 | 按「本谱系收尾文档 / 设计文档改动 / 旧草稿归档 / 无关改动」四类归组，给出拟议 commit 分组与中文 message |
| 验收 | 每组列出具体文件；明确标出「无关改动不纳入本次提交」；未执行 `git add` / `git commit` |

#### Phase 6 提示词模板

```text
请整理当前 git 工作区并给出分组提交建议，但不执行任何提交。要求：
1. 运行 git status --short，按四类归组：本谱系收尾文档、设计文档改动、旧草稿归档、无关改动。
2. 每组列出具体文件，并对无关改动标明不纳入本次提交。
3. 给出拟议的 commit 分组与中文 message。
4. 不要执行 git add 或 git commit。
```

### Phase 7 — 结项报告

| 项 | 内容 |
| :--- | :--- |
| 目标 | 汇总收尾结果，供人工验收 |
| 动作 | 覆盖：审计结论、状态对齐 diff 摘要、三层目录盘点与异常项、artifact map 路径与 canonical 结论、复现锚点路径、问题移交清单路径、git 分组建议、阻塞与未完成项 |
| 验收 | 报告覆盖上述 8 项；明确列出未完成项与原因 |

## 3. 阻塞处理（硬约束）

执行过程中若出现**任何**需要人工确认的问题，或遇到**任何**阻塞：

1. **禁止直接结束、禁止静默跳过、禁止自行假设后继续。**
2. 必须通过交互式提问向人工确认，**一次能问完的合并到同一次提问里**。
3. 提问必须结构化，每项写明：问题描述 / 可选项 / 各选项影响 / 不确认的后果。
4. 收到答复前保持等待，不擅自推进后续 Phase。

**典型需要停下提问的情形**：

1. 目录盘点发现结构异常，无法判断归类
2. 同一逻辑实验存在多个候选 canonical
3. 状态对齐时发现文档描述与实际落盘结果不一致
4. git 工作区存在与本任务边界重叠的既有改动
5. 问题清单中某条归属阶段存在歧义

**只有彻底无法继续才允许结束**（且结束前仍要先用提问说明）：

1. 指定解释器不可用
2. 目标文件结构与规范明显不符，无法安全定位
3. 目标文件上存在与本任务冲突的未提交改动
4. 需要删除或改写现有工件才能继续

---

## 4. 收尾完成标准

当以下同时满足时，可判定该谱系已正式收尾：

1. 谱系全局文档的状态已同步
2. 各设计子文档状态已同步
3. git 工作区中该谱系收尾改动边界已明确
4. 已有可引用的关键结论锚点（canonical artifact map）
5. 已有可执行的复现说明
6. canonical / failed / aborted 口径已冻结
7. 导航入口可作为独立入口到达

---

## 5. 与知识冻结的关系

收尾（本 playbook）解决的是「**工程收口**」；知识冻结解决的是「**知识可携带**」。二者关系：

1. 收尾 Phase 3 产出的 artifact map，是知识冻结中「关键结论 ↔ experiment_version 对照」的依据。
2. 收尾 Phase 5 产出的问题清单，是知识冻结中「需规避的问题」的输入。
3. 一个谱系收尾完成后，应补一份 `closure.md`（该谱系的冻结结论）；原始 generated 报告与 analysis_report 相关文件原则上归档保留。若未来仅做目录迁移而不做删除，也不能让结论只挂在 `outputs/` 下。

知识面组织方式见 [00_start_here.md](00_start_here.md) 与 `docs/` 目录。
