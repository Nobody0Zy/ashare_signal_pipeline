# 02_reference_conclusions

这页不是实验日志，也不是完整复盘；它只保存第一轮历史实验中可迁移、可复核、可在新样本族继续复用的结论与数值锚点。

使用方式：

- 需要判断某种方向是否已经被证伪时，先看 §2。
- 需要给新的谱系设立基线心智模型时，先看 §1。
- 需要做重构/迁移后的 sanity check 时，引用 §3 的锚点，不要把它们当成跨数据集目标值。

## §1 谱系总表

| 谱系 | 核心问题 | 结论 |
| :--- | :--- | :--- |
| v0 | baseline | 建立基线，但含日历泄露 |
| v1 / v2 | 框架摸索 | 无实质结论 |
| v3 | 特征扩展 | 发现日历泄露（gain 份额 69.8%） |
| v3_clean | 干净基线消融 | tsfresh 扩容是最大单因素增益 |
| v4_1 | 机制拆解 | volume 是最大单因素收益；OHLC pure 最弱 |
| v5 (v51) | tsfresh 工具边界 | medium 是拐点档；full 在默认容量下被压制 |
| v5 (v52) | LightGBM 容量边界 | 容量错配只在 full 档成立；medium 放大有害 |

补充解释：

- 第一轮历史实验的最大价值，不是沉淀“固定最优参数”，而是识别哪些方向值得继续、哪些方向必须回避。
- 能迁移的，是机制结论、失效模式与度量口径；不能直接迁移的，是具体样本数、时间区间与策略收益水平。
- 因为不同样本族的数据分布不同，锚点只用于识别“是否明显异常”，不用于要求新谱系复现相同数值。

## §2 已证伪方向

以下判断都已经有明确反例；引用时必须连同证据一起出现。

1. 「加更多 tsfresh 计算器一定更好」  
   证据：full 档在 default 容量下 test Spearman 最低（0.0386）。

2. 「容量越大越好」  
   证据：medium 档容量放大后单调下滑（0.0969 → 0.0898 → 0.0825）。

3. 「用低容量模型的 gain 判断特征价值」  
   证据：full 档放大容量后 test Spearman +19.4%。

4. 「去掉日历特征就会提升实盘排序」  
   证据：Spearman 上升可能由极端预测抬高，须看尾部指标。

这四条共同指向同一个方法论事实：

- 结论不能脱离模型容量成立。
- 结论不能脱离指标语义成立。
- 结论不能脱离时间隔离与泄露诊断成立。
- 结论不能脱离 clean 对照成立。

历史实验还提供了两个更抽象的约束：

| 约束 | 含义 |
| :--- | :--- |
| 归因前先 diff 配置 | 任何“单变量”说法都应能被字段级对比复核 |
| 先区分排序与分层 | test Spearman 与 MonoScore / uplift 不能混用 |

## §3 数值锚点表

| 锚点 | 值 |
| :--- | ---: |
| v51 compact / medium / broad / full（default 容量） | 0.0802 / 0.0969 / 0.0820 / 0.0386 |
| v52 full × high_dim | 0.0461 |
| v3 日历特征 gain 份额 | 0.6980 |
| v3_clean expand_tsfresh | 0.3534 |
| v4_1 OHLC pure（C3） | 0.0924 |
| compact 档量纲不可比占比 | 42.3% |

如何使用这些锚点：

1. 把它们当作“历史已知事实”，不要当作任何新样本族的目标值。
2. 如果迁移后的结果在方向上与这些锚点完全相反，优先排查泄露、容量错配与特征口径漂移。
3. 如果某次重构后同一历史样本族的锚点发生明显偏离，就要回到 `docs/11_baseline_fixture_guide.md` 做逐步对拍。

这些锚点覆盖了三类常见 sanity check：

- 工具链是否保住了排序能力的大致层次关系
- 日历泄露是否被重新引入
- 容量扩张是否只在 full 档这类高维场景中释放价值
